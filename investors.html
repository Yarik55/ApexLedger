The AI layer

The AI codes it. A qualified human signs it.

An assistant that answers from a client's real ledger is only an asset if a practice can defend it to a regulator, a professional body and its own PI insurer. The constraints were designed first and the feature second.

  • Consent is a database fact — timestamped, evidenced, and re-checked when the reply is written, not only when it is requested
  • Answers are attributable — every AI message is flagged in the database and labelled wherever it appears, so it can never read as the accountant's own words
  • Scope is enforced — accounting, tax and portal questions only; instructions embedded in a client's message do not change its behaviour
  • Identifiers never leave the country — TFN, Medicare and account-shaped numbers are masked before any text reaches the model
  • It cannot act — it reads and explains; it cannot lodge, pay, move money or alter a record
Where the work lives

Microsoft-native, because that is where practices already are.

Australian accounting firms run on Microsoft 365. A tool that asks staff to watch another inbox loses to one that appears where they already work — so the practice side of ApexLedger lives in Teams.

  • Client messages arrive as cards in the practice channel; staff reply inside the card
  • Every AI answer is forwarded and flagged, so nothing is said in the practice's name unseen
  • No Azure subscription and no bot registration required
  • A read-only practice API is built for a Copilot agent — read-only by design, so an agent driven by natural language cannot alter client records

Copilot serves licensed users inside a firm's tenant, so it cannot serve the firm's clients, who have no licences. Two deliberately different products: Copilot for staff in Teams, the portal assistant for clients.

The build-out

What completing it actually takes.

The platform is the part that is done. What remains is getting data in, the integrations firms will not work without, and the control layer that makes AI defensible to a professional body. These are numbered because they genuinely depend on each other — later items are not useful without earlier ones.

  1. Automated transaction feeds

    Without them there is no AI-driven practice, only a portal with manual entry. Full Consumer Data Right accreditation is slow and costly, so the practical route is an accredited intermediary. This gates everything below it.

  2. Classification with confidence scoring

    The model proposes a code and how sure it is. High confidence posts automatically; anything below the threshold queues for a human. This is the labour saving the whole proposition rests on.

  3. Review queue and immutable audit trail

    What the model proposed, which version produced it, who approved it, when. Built alongside classification, never after — it is what a PI insurer and a professional body will ask to see, and retrofitting an audit trail is not credible.

  4. Xero and MYOB integration

    Practices will not migrate off their ledger. Sitting on top of it as the AI layer is a far easier sale than replacing it, and turns our own cashbook into an internal detail rather than a competing product.

  5. Document capture

    Receipts and invoices read into structured data and matched to transactions, with an email intake address for supplier bills. Closes the substantiation gap that costs practices the most chasing.

  6. Enterprise readiness

    Entra ID single sign-on, point-in-time backups and a documented recovery plan, penetration testing, and a security questionnaire pack. Mid-tier firms ask for SOC 2 or ISO 27001, a six-to-twelve month exercise worth starting before it is demanded.

Deliberately excluded: lodging returns and activity statements ourselves. That requires Tax Practitioners Board registration and ATO software accreditation. The platform is built so the practice lodges under its own registration, which is both the faster path and the correct one.

Stated plainly

What this is not, yet.

A brief that only lists strengths is not worth reading. The gaps, so they come from us rather than from due diligence:

  • No paying customers to date — the platform has been built and run against a live dataset, not sold
  • Practice licensing is not priced — the prices published on this site are for bookkeeping services, a different product
  • Not a registered tax or BAS agent — ApexLedger does not lodge; the platform is built so the practice using it lodges under its own registration
  • The AI assistant is a demonstration build and is labelled as such in-product, to every client who uses it
  • Production hosting of the practice portal is being finalised
